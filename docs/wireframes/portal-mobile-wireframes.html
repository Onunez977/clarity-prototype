Review notes

Each screen keeps one dominant action and one secondary action, with copy that makes tenancy, permission, and staleness explicit.

Login / default

  • Front-loads permission and mapped-kit checks before the user reaches data-bearing screens.
  • Uses large primary CTA and a secondary path into access states for review discussions.
  • Installability is hinted at through shell framing instead of implementation-specific controls.

Required coverage

  • Login plus multiple access outcomes
  • Dashboard metrics: scan volume, hit count, repos affected
  • Map toggles: geohash-5 hits, address heatmap, owned-order, staging
  • Trip history presets: Today, This Week, Last Week, Month
  • Loading, empty, and error variants for each core surface
