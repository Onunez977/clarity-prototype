## Ticket (live, re-fetched 12:28pm CDT — authoritative)
Key: DEV-2934 · Task · To Do · Sprint 42 · App Clarity · Repo insight-lpr/platform · Epic DEV-1580 · relates to DEV-2928 (PR #510 merged into main as 43255f51)
URL: https://insightlpr-team.atlassian.net/browse/DEV-2934 · Jira cloudId: 150e0ba0-1d8e-4ac4-82da-ee78a512c3cc
Summary: RDN case info: treat "API key not authorized for this case" 500 as a miss, not a retryable failure (follow-up to DEV-2928)

Problem (verbatim): During the pre-prod RDN dry run for org 167 (DEV-2928), one case (hotlist 31963346) came back from RDN as an HTTP 500 with the body "API key not authorized for this case". `GetOrgHotlistCaseInfo` treats any 500 as a transport failure and retries it, so a case like this one is retried forever. It never succeeds, and every retry costs another RDN call under the `rdn-case-info:{org}` limiter. This is very likely existing job behaviour, but `app:rdn-backfill-branches` calls the same `handle()` path in-process, so the backfill hits it too.

Fix (verbatim): Detect this specific RDN response, a 500 whose body says the API key is not authorized for the case, and treat it as a permanent miss for that hotlist:
* Do not retry it and do not rethrow it as a transport failure.
* Leave `branch_id` untouched, the same as a case with no branch.
* In `app:rdn-backfill-branches`, count it in the miss / no-match bucket of the summary instead of as an error.
* All other 500s and transport errors keep the current retry behaviour.
Simplest thing first: this is a classification change in the existing error handling. No new queue, job, throttle, or config.

Acceptance criteria (verbatim):
- AC1: A not-authorized 500 for a case is recorded once as a miss and is not retried, in both the job path and the backfill command.
- AC2: Other 500s and connection errors are still retried as before.
- AC3: Feature tests cover the not-authorized 500 for both the job and the command (dry run and live), plus a regression test for a generic 500.
- AC4: The API key and any secrets never appear in logs, test output, or the PR.
Out of scope: the duplicate RDN branch "Action Towing & Recovery Orlando " (RDN ids 20576 and 21849).

PM ruling (Dalton, 12:23pm CDT): the RDN SOAP fault "This API key is not authorized to access this case" (HTTP 500) = MISS, not endless transport retry.
Literal fault text as logged by RDN.php L122 in the DEV-2928 dry run: `This API key is not authorized to access this case`. The ticket's paraphrase is NOT the literal string — match the logged text.
