**Plan: implementation plan for DEV-2934**

Branch path: main→main · draft PR https://github.com/insight-lpr/platform/pull/512

**Approach**
RDN's per-case refusal, an HTTP 500 SOAP fault reading "This API key is not authorized to access this case", becomes a permanent miss. Today it is treated as a transport failure that retries forever. `RDN::call()` keeps the exception it already catches and exposes it through one getter next to `lastCallCompleted()`. `GetOrgHotlistCaseInfo` gets one static check, `isCaseRefusal()`. `handle()` and the dry-run `classify()` both use it, just before their existing transport check. On a refusal, the job reuses the existing atomic miss upsert with one optional `seal` flag. The flag writes `branch_lookup_attempts` to the ceiling, and the job emits the existing `miss_no_branch_name` outcome. The live backfill runs `handle()` inline, so it inherits the fix with no change.

**Blast radius**
- `app/Services/RDN.php`: one property and one getter. The catch, the return shape and every other caller are unchanged.
- `app/Jobs/Rdn/GetOrgHotlistCaseInfo.php`: `isCaseRefusal()`, a refusal branch in `handle()`, and an optional `seal` parameter on `recordUnresolvedLookup()`.
- `app/Console/Commands/RdnBackfillBranches.php`: the `classify()` mirror (dry run only).
- Not touched: `config/horizon.php`, `config/services.php`, `GetOrgHotlistCases`, `RdnJob` and its subclasses, and the other RDN callers.
- Data: PostgreSQL only (the existing `hotlist_json` upsert). ClickHouse: none, **ch_touch: no**. No migrations, routes or config.
- Simplest first: everything is inline in existing paths. No new queue, job, throttle, Horizon change, config key, class, metric or outcome.

**Narrow-match guard**
The match requires a SoapFault AND the case-insensitive phrase "not authorized to access this case". A broader match would seal every row during an org-wide key rotation, and a sealed row has no un-seal path. Generic 500s, connection errors, key-wide refusals and the ticket's paraphrase stay `transport_failed`. Tests pin both sides.

**Decided defaults**
- Seal on the first refusal: the counter is written to the ceiling, so RDN is not called again for that row.
- No new column in the live summary. A refusal counts as processed, not failed. The dry run shows it under `miss_no_branch_name`.

**Test plan**
- Run: `GetOrgHotlistCaseInfoTest`, `RdnBackfillBranchesTest`, `RDNTest`, `GetOrgHotlistCasesTest`.
- Add (job):
  - a refusal seals on first sight and is not re-dispatched
  - a refusal emits `miss_no_branch_name`, not `transport_failed`
  - a refusal on a row with a prior miss seals
  - a generic 500 stays transport and is re-dispatched
  - a key-wide refusal stays transport
  - predicate pins: the literal, case variants, the paraphrase, a non-SoapFault and null
  - the API key never appears in any log
- Add (command):
  - a `DENIED` stub arm
  - a live run seals it (failed 0), and a re-run does not call RDN for it
  - a dry run counts it as `miss_no_branch_name` and writes nothing
  - `DENIED` added to the dry-run vs job parity loop
  - the API key is absent from output and logs on both the live and dry runs
- Add (service): the kept exception is reset on the next call.
- Provision: keyed test database only, with no site or ClickHouse environment. Agent QA is suites only.

**Open questions (non-blocking)**
- RDN's fault code for the refusal was not captured, so the match ignores the fault code. If RDN rewords the text, the case falls back to transport, which is the safe direction.
