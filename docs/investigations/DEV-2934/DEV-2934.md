# DEV-2934: RDN case info: treat "API key not authorized for this case" 500 as a miss, not a retryable failure (follow-up to DEV-2928)

Worktree for this run: branch `cursor/dev-2934-rdn-unauthorized-case-miss`, tip 03a45aef (43255f51 + one docs-only prep commit). Code below was read at that tip; line numbers match the recon in First Glance (Jira comment 43378).

## 1. Summary and intent
RDN answers some cases with an HTTP 500 SOAP fault whose faultstring is `This API key is not authorized to access this case` (literal text logged by `app/Services/RDN.php` L122 during the DEV-2928 dry run, hotlist 31963346). Today `RDN::call()` catches every exception (L121–125), returns `EMPTY_RESULT` (L128–129) and leaves `lastCallCompleted` false (L108), so `GetOrgHotlistCaseInfo::handle()` takes the transport branch (L418–421): no write, no attempt spent, re-selected on every run forever. The backfill command inherits this in its live loop (`RdnBackfillBranches.php` L168) and mirrors it in its dry run (`classify()` L313–314).

Intent: classify that one per-case refusal as a permanent miss. It is recorded once, the row is sealed on the first refusal and `branch_id` is left as a no-branch miss leaves it. This applies in the job, the live backfill and the dry-run backfill. Every other fault and transport error keeps today's transport handling. The API key never appears anywhere.

PM ruling (Dalton, 12:23pm CDT): this fault counts as a MISS. Match the logged text. The ticket's paraphrase ("API key not authorized for this case") is not RDN's string.

Decided defaults (from First Glance; they stand unless Dalton says otherwise):
- D1. SEAL ON FIRST REFUSAL. On the first refusal, `branch_lookup_attempts` is written to `GetOrgHotlistCaseInfo::maxLookupAttempts()`, which is 3 as shipped. A plain +1 miss would still call RDN up to 3 times, and the AC says "not retried".
- D2. NO new column in the live command summary (walked / processed / failed, `RdnBackfillBranches.php` L189–214). A refusal already counts as processed, not failed, because `RDN::call()` swallows it and `handle()` returns normally. The miss is visible as the sealed counter and the existing `rdn_case_info.miss_no_branch_name` count. The dry-run table already has a `miss_no_branch_name` column (L235–240).

## 6. Implementation steps (ordered)
1. **`app/Services/RDN.php`**
   - Under L31, add `private ?\Exception $lastCallException = null;` with a one-line docblock: "The exception the most recent call() caught, if any. See lastCallException()."
   - At L108, add `$this->lastCallException = null;` next to the `lastCallCompleted` reset.
   - In the catch (L121–125), add `$this->lastCallException = $exception;`. Keep the existing `Log::error` line exactly as is (it logs the fault message and `org_id` only).
   - After `lastCallCompleted()` (L104), add `public function lastCallException(): ?\Exception`. Its PHPDoc says the fault is kept so a caller can tell a per-case refusal from a transport failure, and that, like `lastCallCompleted()`, it must be read immediately after the call it describes. Never log or serialize it.
2. **`app/Jobs/Rdn/GetOrgHotlistCaseInfo.php` — static check.** Below `normalizeBranchName()` (after L288), add:
   ```php
   /**
    * Whether RDN refused this ONE case for this key (HTTP 500 SOAP fault "This API key is
    * not authorized to access this case"). A permanent per-case answer: the row is sealed
    * as a miss. Deliberately narrow - a key-wide refusal, any other fault or a transport
    * error must stay transport_failed, because a seal has no un-seal path and no TTL.
    * app:rdn-backfill-branches --dry-run calls this too.
    */
   public static function isCaseRefusal(?\Throwable $exception): bool
   {
       return $exception instanceof \SoapFault
           && Str::contains($exception->getMessage(), 'not authorized to access this case', ignoreCase: true);
   }
   ```
   (`Str` is already imported at L19.)
3. **`handle()`.** Immediately before `if (! $rdn->lastCallCompleted())` (L418), insert:
   ```php
   if (self::isCaseRefusal($rdn->lastCallException())) {
       $this->recordUnresolvedLookup(seal: true);
       $this->recordOutcome(self::OUTCOME_MISS_NO_BRANCH_NAME);

       return;
   }
   ```
   It must come before the transport check, because a refusal also leaves `lastCallCompleted()` false. Add one sentence to the comment block at L411–417 noting that the per-case refusal is the single fault that counts as an answer.
4. **`recordUnresolvedLookup(bool $seal = false): void`** (L510). This is the chosen way to write the ceiling, reusing the one atomic upsert:
   - Compute `$floor = $seal ? self::maxLookupAttempts() : 0;`.
   - Insert branch: replace `'1'::jsonb` (L523) with `to_jsonb(greatest(1, ?::numeric))`.
   - Conflict branch: wrap the existing `(case ... end) + 1` (L536–542) as `to_jsonb(greatest((case ... end) + 1, ?::numeric))`.
   - Bindings become `[$this->hotlist->id, $floor, $now, $now, $floor, $now]`.
   - Add one PHPDoc line: "`$seal` writes the counter to at least the ceiling, for an answer that will never change (isCaseRefusal())."
   - Why this pick: with `$floor = 0` the normal miss is byte-for-byte the same value (insert 1, update +1, fractional 1.5→2.5 preserved per L945). The `ENRICHED_PREDICATE` guard that never blanks a resolved `branch_id` (L528–533) is inherited. The seal is atomic in the same single statement.
   - Rejected alternatives: (a) a second SQL statement duplicates the upsert and its guards; (b) a plain +1 calls RDN up to 3 times, which breaks "not retried"; (c) an `int $increment = ceiling` overshoots, so the counter would read 4–5 and stop meaning attempts, and the test could not pin `=== maxLookupAttempts()`.

## Narrow-match risk (named risk + guard)
**Risk:** a broad match (any HTTP 500, any `SoapFault`, "API key", or "not authorized" alone) would also catch an org-wide key rotation or revocation. Every row that run touched would be sealed, and there is no un-seal path and no TTL (`GetOrgHotlistCaseInfo.php` L411–417 comment; `sealedPredicate()` L98–102).
**Guard:** `$e instanceof \SoapFault` AND a case-insensitive substring match on `not authorized to access this case`. Generic 500s, transport errors, a null client (there is no exception, so the check returns false), a non-SoapFault exception carrying the same text, key-wide refusals and the ticket paraphrase all stay `transport_failed`. Tests 4, 5 and 6 pin the negative side and tests 1, 3, 9 and 10 pin the positive side.
**Residual (non-blocking):** raising the ceiling later by config (for example lookback 6 days → ceiling 5, per test L864) re-opens refused rows. They are called once more and then re-sealed at the new ceiling. That is today's semantics for every miss, so it is accepted as is.
