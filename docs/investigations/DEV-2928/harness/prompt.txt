## Acceptance criteria (live Jira)
1. Backfill command `app:rdn-backfill-branches {org} --since= [--until=] [--chunk=500] [--max=] [--dry-run=N]`. Dry-run calls RDN for N sample hotlists spread across age buckets (<30d, 30–180d, >180d), writes NOTHING, reports resolved / no_branch_name / no_branch_match / transport_failed per bucket plus unmatched `vendor_branch_name` values next to the org's branch names.
2. Running it enqueues `GetOrgHotlistCaseInfo` only for the org's RDN hotlists with activity in the window (status transition or repo date in the window, or currently Open/Hold), not already resolved/sealed, newest→oldest; selection by activity, not created_at. Throttled chunks pushed only while the queue is short (job retryUntil ~48h). Dedicated queue (e.g. `rdn-backfill`, not `{low}`) + Horizon supervisor entry. Resumable per-org cursor; safe to re-run.
3. Branch match: exact first; normalized fallback (trim, case-insensitive, collapse whitespace/punctuation). Exact still wins when present.
4. With a branch selected, LPR Assists and Missed Opportunities count rows whose hotlist CURRENTLY has that branch, including hotlists enriched after the recovery / missed-hit row was written. Unfiltered (All Branches) numbers unchanged.
5. Tests cover: selection window, chunking + resume, dry-run no-write, normalized matching, query-time branch filter for both cards.
